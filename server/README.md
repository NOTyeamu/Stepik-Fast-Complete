# Хранилище ответов: Google Apps Script + таблица

Почему так: **у гистов GitHub нет соавторов** — писать в гист может только владелец токена,
поэтому «гист, в который пишут все» создать нельзя. Единственные два пути — раздать всем
токен владельца (так работало до сих пор, токен при этом лежит в открытом репозитории) или
завести своё хранилище.

Этот вариант — своё. В скрипте у людей **нет никаких секретов**, только URL веб-приложения.
Ответы лежат в обычной Google-таблице: видно, кто что добавил, можно править руками,
скачать в CSV, отключить доступ — переразвернуть приложение.

## Что понадобится

Аккаунт Google (обычный). Больше ничего: ни карты, ни сервера, ни консоли.

## Развёртывание (5 минут)

1. Открой <https://sheets.new> — создастся новая пустая таблица. Назови как хочешь,
   например `Stepik answers`.
2. В таблице: **Расширения → Apps Script**. Откроется редактор скриптов.
3. Удали то, что там есть по умолчанию (`function myFunction() {}`), и вставь целиком
   содержимое файла [`apps-script.gs`](apps-script.gs) из этого репозитория.
4. Нажми **Сохранить** (значок дискеты), затем **Развернуть → Новое развёртывание**:
   - *Тип*: **Веб-приложение**
   - *Описание*: `Stepik answers`
   - *Запуск от имени*: **Я**
   - *У кого есть доступ*: **Все** ← обязательно, иначе скрипт у других людей не сработает
5. Нажми **Развернуть**. Google попросит подтвердить доступ — это нормально:
   *Дополнительные настройки → Перейти к проекту (небезопасно) → Разрешить*.
   Права нужны только на таблицу, которую ты создал.
6. Скопируй **URL веб-приложения** — длинная строка вида
   `https://script.google.com/macros/s/AKfycb.../exec`.
7. Пришли этот URL мне. Дальше я сам:
   - проверю хранилище (запись/чтение),
   - перенесу туда все ответы, которые уже накопились в гисте,
   - обновлю скрипт в репозитории, чтобы он работал с новым хранилищем.

## Как проверить, что работает

Открой URL веб-приложения в браузере — должен вернуться JSON:

```json
{"ok":true,"count":0,"items":[]}
```

В таблице появится лист `answers` с шапкой. Дальше он наполняется сам.

## Что важно знать

- **URL — это и есть доступ.** Кто знает URL, тот может читать и писать. Секрета в скрипте
  нет, но и защита держится только на незнании адреса. Если ссылка утечёт — в Apps Script
  сделай *Развернуть → Управление развёртываниями → Новое развёртывание* и пришли мне новый
  URL: обновлю скрипт, Tampermonkey раздаст его всем сам.
- **Лимиты Google** щедрые для этого сценария: один ответ = одна строка, чтение индекса —
  один запрос на запуск браузера. При 30–50 людях запас большой.
- **Гонок нет.** Раньше все писали в один JSON-файл гиста и затирали друг друга; теперь
  каждый ответ — отдельная строка, запись идёт под блокировкой.
- **Бэкап** — это сама таблица: *Файл → Скачать → CSV*.

## Если хочется другой бэкенд

Тот же интерфейс (`GET` индекса, `GET ?key=`, `POST {items:[…]}`) можно поднять где угодно —
Cloudflare Workers + KV, Supabase (таблица + RLS на чтение/вставку), Deno Deploy. Скрипт
общается с хранилищем по HTTP, поэтому замена серверной части не требует правок в браузере.

## Ещё одно: прокси для ИИ (по желанию)

Тот же Apps Script умеет работать **прокси для ИИ**. Зачем: ключ доступа нельзя спрятать
в браузере — скрипт, который им пользуется, приносит ключ в браузер, и любой, кто поставил
скрипт, может его достать. Если ключ положить **сюда**, в браузер он не попадает вообще.

**Включить (один раз):**

1. В редакторе Apps Script: **Настройки проекта → Свойства скрипта → Добавить свойство**:
   - `AI_KEY` — ваш ключ доступа к ИИ (обязательно);
   - `AI_ENDPOINT` — адрес сервиса, если он не тот, что по умолчанию (необязательно).
2. **Развернуть → Управление развёртываниями → Изменить → Новая версия → Развернуть.**
3. Скопировать адрес веб-приложения и вписать его в скрипт: значок Tampermonkey →
   **«🌐 Прокси ИИ»**.

С этого момента все запросы к ИИ идут через ваш Apps Script, а ключ остаётся в свойствах
скрипта. В браузере ключа нет — ни в исходнике, ни в запросах.

**Ограничения Google, о которых стоит знать:**

- один запрос должен уложиться в **60 секунд** (столько даёт `UrlFetchApp`), а всё приложение —
  в **6 минут**. Сильная модель с длинными размышлениями в это не всегда укладывается;
- лимиты бесплатного аккаунта: около 20 000 запросов в сутки на `UrlFetchApp` — для
  нескольких десятков человек с запасом;
- прокси отвечает кодом 200 всегда (так устроен `ContentService`), поэтому настоящий код
  ответа провайдера лежит в теле, в поле `status`. Скрипт это понимает и показывает
  внятную ошибку.

Если хочется другой бэкенд — тот же интерфейс (`POST {ai:{…}}` → ответ провайдера как есть)
поднимается где угодно: Cloudflare Workers, Deno Deploy, Vercel. Главное — держать ключ
на сервере и отвечать телом с полем `status` при ошибке.
