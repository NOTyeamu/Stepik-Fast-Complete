# Stepik Fast Complete

Юзерскрипт для Tampermonkey: зачтённые ответы Stepik автоматически складываются в общий
GitHub Gist, а на шаге, где решение уже есть, справа от карточки задания появляется
скоба **«есть решение · вставить / нет»**.

## Установка

1. Поставьте [Tampermonkey](https://www.tampermonkey.net/) (Chrome, Edge, Firefox, Opera).
2. Откройте файл скрипта и нажмите «Установить»:

   **https://raw.githubusercontent.com/NOTyeamu/Stepik-Fast-Complete/main/stepik-gist-sync.user.js**

   _(Tampermonkey сам предложит обновиться, когда в репозитории появится новая версия — в
   шапке скрипта прописаны `@updateURL` и `@downloadURL`.)_
3. Откройте любой урок на stepik.org. Токен уже вшит, настраивать ничего не нужно.

## Как это работает

Раньше ответ выковыривался из DOM: скрипт искал редактор CodeMirror, разбирал вёрстку,
угадывал, зачтён ли шаг. Любое обновление интерфейса Stepik ломало запись — ответы
переставали сохраняться у всех сразу.

Теперь ответ берётся у самого Stepik, через запросы:

| Что | Запрос |
| --- | --- |
| id шага по номеру из адреса | `GET /api/lessons?ids[]=<урок>` → `steps[номер-1]` |
| кто я (чтобы не сохранить чужое) | `GET /api/users/me` |
| зачтённый ответ | `GET /api/submissions?step=<id>&limit=20` → `status: "correct"`, `reply.code` / `reply.choices` |

Плюс перехватываются сетевые запросы самой Stepik (`fetch` и `XMLHttpRequest`): в момент
нажатия «Отправить» ответ уходит в гист сразу, ещё до того как страница перерисуется.
Если список шагов в API недоступен, id шага берётся из этого же перехвата и проверяется
через `GET /api/steps/<id>` (сверяются `lesson` и `position`).

В гист уезжает:

```
stepik_l<урок>_s<шаг>.<язык>   — код решения        (например stepik_l1793281_s8.cs)
stepik_l<урок>_s<шаг>.json     — тест с вариантами  {"type":"choice","ids":[222],"answers":["второй"]}
```

Файла-индекса больше нет: **список файлов гиста и есть индекс**, ключ шага выводится из
имени файла. Поэтому несколько человек могут писать одновременно и не затирать друг
друга — раньше общий `_stepik_index.json` перезаписывался целиком и записи терялись.

## Переезд на своё хранилище

Гист — вынужденное решение: **у гистов нет соавторов**, писать может только владелец токена,
поэтому токен приходится раздавать всем в открытом виде. Плюс лимит 5000 запросов в час
общий на всех пользователей.

Рядом лежит [`server/`](server/) — свой бэкенд на Google Apps Script + Google-таблице:

- один ответ = одна строка таблицы, а не перезапись общего файла;
- в скрипте у людей **нет никаких секретов** — только адрес веб-приложения;
- видно, кто какой ответ добавил; можно править руками, скачать в CSV, отключить доступ.

Инструкция по развёртыванию — [`server/README.md`](server/README.md). Скрипт переключится
на это хранилище в версии 4.0.0, как только оно будет развёрнуто.

## Меню Tampermonkey

| Пункт | Что делает |
| --- | --- |
| ⚙ Токен и gist | сменить токен, ID гиста и дополнительный гист «только для чтения» |
| 🧪 Тест записи в гист (отчёт) | реально пишет тестовый файл и показывает, что ответил GitHub и Stepik |
| 🔍 Проверить доступ к гисту | чей гист, чей токен, можно ли писать |
| 📂 Открыть гист, куда идёт запись | ссылка на гист |
| ♻ Вернуть общий гист | сбросить настройку на гист по умолчанию |

Горячие клавиши: `Ctrl+Alt+I` — вставить решение, `Ctrl+Alt+S` — перезаписать принудительно,
`Ctrl+Alt+D` — отчёт самопроверки.

## Если не сохраняется

**У гистов нет соавторов.** Писать в гист может только владелец токена — это ограничение
GitHub, а не скрипта. Поэтому все пишут токеном владельца общего гиста (он вшит в скрипт).
Если токен чужой для этого гиста, скрипт один раз за сессию создаст **личный** гист, а общий
оставит для чтения и скажет об этом тостом.

**Лимит запросов.** У токена 5000 запросов в час. Если лимит исчерпан, GitHub отвечает
`403 rate limit exceeded`, и скрипт замолкает до конца окна, показывая, сколько ждать.
Опрос Stepik API идёт с растущим интервалом (3с → 5с → 8с → … → минута), а не в цикле
каждые 800 мс, как было раньше — именно старый цикл выжигал лимит всем сразу.

## Безопасность

Токен владельца гиста лежит прямо в файле, а файл — в открытом репозитории. Это значит,
что **любой, у кого есть скрипт, может читать и писать в этот гист**. Токен разбит на
куски только для того, чтобы GitHub не отозвал его автоматически (secret scanning ищет
непрерывную строку). Если это не подходит — заведите отдельный аккаунт-«хранилище», токен
только с правом `gist` и смените его в меню «⚙ Токен и gist».
