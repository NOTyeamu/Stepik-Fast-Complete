# Stepik Fast Complete

Юзерскрипт для Tampermonkey: зачтённые ответы Stepik автоматически складываются в папку
[`answers/`](answers/) этого репозитория, а на шаге, где решение уже есть, справа от карточки
задания появляется скоба **«есть решение · вставить / нет»**.

## Установка

1. Поставьте [Tampermonkey](https://www.tampermonkey.net/) (Chrome, Edge, Firefox, Opera).
2. Откройте файл скрипта и нажмите «Установить»:

   **https://raw.githubusercontent.com/NOTyeamu/Stepik-Fast-Complete/main/stepik-gist-sync.user.js**

   _(Tampermonkey сам предложит обновиться, когда в репозитории появится новая версия — в
   шапке скрипта прописаны `@updateURL` и `@downloadURL`.)_
3. Откройте любой урок на stepik.org. Настраивать ничего не нужно.

> **Как обновить уже установленный скрипт.** Tampermonkey сам проверяет обновления примерно
> раз в сутки, поэтому после новой версии в репозитории кнопки может ещё не быть. Зайдите в
> Dashboard Tampermonkey → «Проверить обновления скриптов» (или значок Tampermonkey →
> «Проверить обновления скриптов»). Если версия всё ещё старая — подождите пару минут:
> сам файл по ссылке тоже обновляется с задержкой до 5 минут.

## Как это работает

Ответ не выковыривается из вёрстки — он берётся у самого Stepik, через запросы:

| Что | Запрос |
| --- | --- |
| id шага по номеру из адреса | `GET /api/lessons?ids[]=<урок>` → `steps[номер-1]` |
| кто я (чтобы не сохранить чужое) | `GET /api/users/me` |
| зачтённый ответ | `GET /api/submissions?step=<id>&limit=20` → `status: "correct"`, `reply.code` / `reply.choices` |

Плюс перехватываются сетевые запросы самой Stepik (`fetch` и `XMLHttpRequest`): в момент
нажатия «Отправить» ответ уходит в хранилище сразу, ещё до того как страница перерисуется.
Если список шагов в API недоступен, id шага берётся из этого же перехвата и проверяется
через `GET /api/steps/<id>` (сверяются `lesson` и `position`).

## Где лежат ответы

```
answers/index.json           список: ключ шага → файл, язык, вид (код или тест)
answers/l<урок>_s<шаг>.cs    код решения        (например answers/l1793281_s8.cs)
answers/l<урок>_s<шаг>.json  тест с вариантами  {"type":"choice","ids":[222],"answers":["второй"]}
```

Читаются обычными ссылками с `raw.githubusercontent.com` — репозиторий публичный, никаких
прав для чтения не нужно.

**Пишет в `answers/` только робот** — workflow [`answers.yml`](.github/workflows/answers.yml).
Скрипт в браузере кладёт новый ответ в очередь `inbox/`, робот переносит его в `answers/`,
пересобирает `index.json` и убирает очередь. Он же **откатывает любые правки `answers/`,
сделанные не им** — так ответы нельзя ни испортить, ни удалить. Существующий ответ не
перезаписывается никогда: папка только пополняется.

Почему так, а не «просто гист»: **у гистов GitHub нет соавторов**, писать может только
владелец токена — а такой токен в открытом репозитории открывает доступ ко всем гистам
аккаунта и даёт общий лимит 5000 запросов в час на всех.

## Меню Tampermonkey

| Пункт | Что делает |
| --- | --- |
| ⚙ Токен записи | токен с правом `Contents: write` (нужен только для сохранения) |
| 🧪 Проверка хранилища (отчёт) | читает список ответов, проверяет токен и текущий шаг |
| 📄 Пройти задания / собрать в Word | панель обхода и сборки документа |
| ✨ ИИ: решить текущий шаг | спросить ИИ про задание, которого нет в ответах |
| 📋 Показать решение от ИИ | открыть последнее решение ИИ |
| 🔑 Настройки ИИ | ключ своего канала; пусто — только бесплатный |
| 🔄 Обновить список ответов | подтянуть свежий `index.json` |

Горячие клавиши: `Ctrl+Alt+I` — вставить решение, `Ctrl+Alt+S` — сохранить принудительно,
`Ctrl+Alt+D` — отчёт самопроверки.

Скоба «есть решение» контрастная (белая карточка с синей рамкой и заметными кнопками) и
обрамляет **весь блок задания**, а не отдельный вопрос. Если справа места нет — переезжает
**наверх**, прямо над заданием. Когда сохранённого ответа нет, в скобе появляется кнопка **«ИИ»**.

## Пройти задания пачкой

Панель открывается **кнопкой в шапке урока** — она добавлена в ряд настроек рядом с
полноэкранным режимом и шестерёнкой (та же кнопка есть и в меню Tampermonkey:
**«📄 Пройти задания / собрать в Word»**).

По нажатию панель занимает место списка уроков в боковом меню курса и остаётся в его стиле:
тёмная, с зелёным маркером и таким же отступом. Крестик возвращает уроки на место.

```
┌──────────────────────────────┐
│ ✨ Задания Stepik         ✕  │   ← вместо списка уроков
│  с [ 4.1 ▾ ]                 │
│  по [ 4.3 ▾ ]                │
│  уроков с ответами: 12       │
│  ▶ Пройти и отправить        │
│  ⤓ Собрать в Word            │
│  ✨ Спросить ИИ по шагу      │
│  ⟳ Скачать Word ещё раз      │
│  ■ Остановить                │
│  ▬▬▬▬▬▬▬▬▬▬░░░░░░  62%       │
│  11 из 18: 4.3.2 отправлено  │
└──────────────────────────────┘
```

Пока идёт обход, на кнопке мигает зелёная точка, а прогресс виден ещё и тонкой полоской вверху
страницы. Вкладку лучше не закрывать — между шагами страница перезагружается; задание хранится
локально и переживает перезагрузку.

Для скриншотов и `.docx` подтягиваются две библиотеки с `cdn.jsdelivr.net` (html2canvas и
JSZip). Если CDN недоступен, обход всё равно работает, а документ выйдет без картинок.

Что делают кнопки:

- В списках **«с» и «по» — только те уроки, для которых уже есть сохранённые ответы**
  (номера и названия берутся из бокового меню курса, так что видно ровно то, что на экране).
- **Пройти и отправить** — идёт по всем шагам выбранных уроков, вставляет сохранённый ответ,
  жмёт кнопку отправки и переходит дальше. Шаги без ответа пропускаются.
- **Собрать в Word** — идёт по тем же урокам и снимает скриншоты **только тех заданий, где
  нужно вставлять код**; тесты с галочками и теория пропускаются. В конце собирается `.docx`,
  который сразу скачивается.
- **Спросить ИИ по шагу** — решение для задания, которого нет в ответах (см. ниже).
- **Остановить** — прерывает обход.

## Решение от ИИ (для заданий без ответа)

Если в общей папке ответа на шаг нет, решение можно попросить у ИИ: **кнопка «ИИ» в скобе**,
кнопка **«Спросить ИИ по шагу»** в панели, или меню Tampermonkey → ✨ ИИ: решить текущий шаг.

**Каналов два, и они работают по очереди** — сначала бесплатный, потом свой:

| Канал | Адрес | Модель | Ключ |
| --- | --- | --- | --- |
| бесплатный | `text.pollinations.ai` | `openai-fast` | не нужен |
| свой | `api.reformboss.com/v1` | `glm-5.3-flash`, запасной `deepseek-v4-flash` | нужен |

- **Почему сначала бесплатный.** Ключа у него нет вообще — воровать нечего, лимит общий
  (1 запрос / 15 с) и восстанавливается сам. Это проверено тестом: в теле запроса нет ни
  одного токена (сценарий 24).
- **Почему есть второй.** Бесплатный тариф при перегрузе отвечает **HTTP 402** — тогда скрипт
  сам, не спрашивая, идёт в свой канал и решает там (сценарий 28). Человек видит в статусе
  «бесплатный не смог — пробую свой ключ…», а в окне решения подписано, каким каналом решено.
  Короткую паузу своего канала (1,5 с) скрипт **пережидает**, а не пропускает канал: иначе
  отказ бесплатного обнулял бы запасной путь и человек получал бы «лимит» вместо решения.
- **Если молчат оба** — понятный текст, а не «HTTP 500»: «ИИ не ответил — бесплатный: … · свой
  ключ: …». Редактор и страница не трогаются (сценарий 29).
- **Ключ своего канала можно убрать:** меню → **🔑 Настройки ИИ** → очистить поле. Тогда
  остаётся только бесплатный канал, и в свой запросы не уходят вовсе (сценарий 30).
  Пустое поле — это осознанный выбор «ключа нет», а не «подставь встроенный»: раньше именно
  встроенный ключ и подхватывался, так что убрать его было невозможно. Ключ, который вы не
  задавали сами, по-прежнему берётся из скрипта (сценарий 30a).

**Что важно знать про ключ.** Скрипт целиком работает в браузере, поэтому любой ключ, вписанный
в него, виден тому, кто этот скрипт поставил. Ключ из репозитория разбит на куски и закодирован
(так его не находит автопоиск токенов на GitHub), но это **защита от случайного взгляда, а не от
целенаправленного использования**. Если это не устраивает — очистите поле в «🔑 Настройки ИИ»
и пользуйтесь бесплатным каналом. Полностью закрыть вопрос можно только переносом ключа на
сервер (GitHub Actions + Secrets), и тогда решение придёт из робота, а не из браузера.

Прочее:

- **Ничего не отправляется на проверку.** ИИ только **показывает** текст решения в окне с
  кнопкой «Скопировать». Ни вставки в редактор, ни нажатия «Отправить» нет (сценарий 24).
- **Ответы кэшируются по шагу** — за один и тот же шаг скрипт не спрашивает дважды, а на шагах,
  где сохранённый ответ уже есть, к ИИ не обращается совсем (сценарий 27).
- **Reasoning-модели.** `deepseek-v4-flash` сначала «думает» в отдельном поле и при коротком
  лимите может вернуть пустой ответ — поэтому основная модель `glm-5.3-flash` (около 5 секунд
  против 30), а если `content` пустой, берётся то, что модель всё-таки написала (сценарий 31).

## Если не сохраняется

- **Ответ появился не сразу.** Файл попадает в `inbox/` мгновенно, робот переносит его в
  `answers/` за несколько секунд, но `raw.githubusercontent.com` держит отданный файл в
  кэше до 5 минут — поэтому чужой свежий ответ может стать виден не сразу. Свой ответ видно
  сразу: скрипт добавляет шаг в локальный список, не дожидаясь GitHub.
- **`токену не хватает права «Contents: write»`** — в настройках токена у этого репозитория
  должно быть право *Contents → Read and write*.
- **`токен не видит репозиторий`** — добавь `Stepik-Fast-Complete` в его Repository access.
- **Не работает совсем** — меню → «🧪 Проверка хранилища» (или `Ctrl+Alt+D`). Отчёт пишет
  по шагам: прочитался ли список ответов, работает ли токен, определился ли id шага в API
  Stepik, сколько у вас отправок и с какими статусами, что лежит в редакторе на странице и
  чем закончилась последняя попытка сохранить. По нему сразу видно, где обрыв.

  Частые случаи, когда «не сохраняется», а всё в порядке:
  - **ответ для этого шага уже есть** — тогда появляется скоба «есть решение», сохранять
    нечего;
  - **шаг не того типа** — скрипт умеет только код и тесты с выбором варианта; текстовые
    ответы, числа, сопоставления и сортировки сохранять некуда;
  - **вы ещё не отправили зачтённое решение** — сохранять нечего.

- **«Собрать в Word» ничего не делала.** Так было до версии 6.0.0: обход строится по шагам,
  для которых есть сохранённый ответ, а человек стоит на другом шаге — и скрипт ждал перехода,
  который сам же и должен был сделать. Stepik это одностраничное приложение, и простое
  присваивание адреса страницу не перезагружает: обход стоял на месте. Теперь адрес меняется
  через маршрутизатор, а если так не вышло — через жёсткую перезагрузку; если шаг открыть
  не удаётся, он пропускается с записью в статусе, а не висит вечно.

## Владельцу репозитория

**Токен записи.** Нужен один раз: GitHub → *Settings → Developer settings → Personal access
tokens → Fine-grained tokens → Generate new token*.

- Repository access: **Only select repositories** → `Stepik-Fast-Complete`
- Repository permissions: **Contents → Read and write**, больше ничего
- Скопировать значение и вшить в скрипт (в коде это `DEF_TOKEN`, разбитый на куски — GitHub
  автоматически отзывает токены, найденные в открытом виде).

Что этот токен **не** может: менять файлы `.github/workflows/` (для них нужно отдельное
право `workflows: write`), поэтому выключить или переписать робота им нельзя. Всё, что он
может испортить, робот откатывает.

**Поправить ответ руками.** Робот откатывает правки `answers/` не от своего имени, поэтому
либо коммить от имени робота:

```bash
git -c user.name="stepik-answers-bot" \
    -c user.email="stepik-answers-bot@users.noreply.github.com" \
    commit -m "answers: правка"
```

либо добавь в сообщение коммита маркер `[answers-ok]` — тогда робот правку пропустит.
После ручной правки пересобери индекс: `node .github/scripts/make-index.mjs`.

**Очередь не разобралась** — зайди в *Actions → answers → Run workflow*: робот разберёт
`inbox/` и починит `index.json`. То же самое он делает сам раз в 20 минут.

## Тесты

Скрипт проверяется без браузера — jsdom с подставными GitHub и Stepik:

```bash
NODE_PATH="$HOME/.workbuddy-ai/binaries/node/workspace/node_modules" \
  node test/harness.js
```

119 проверок: автосохранение, вставка кода, тесты с вариантами, перехват отправки, поведение
при недоступном GitHub и при отсутствии токена, панель «от и до», сборка плана из уроков
курса («с 4.1 по 4.3» → все шаги трёх уроков), обход с отправкой, сборка `.docx` (её тест
распаковывает готовый файл и проверяет, что внутри есть картинка, связь и заголовок), переезд
скобы наверх, когда справа нет места, **ожидание редактора, который Stepik дорисовывает с
задержкой**, **быстрый пропуск шага, где вставлять нечего**, **правильный адрес перехода между
уроками** (без чужого `?unit=`), **нажатие именно «Отправить на проверку»** вместо «Решить
снова», **скоба по всему блоку задания**, **список только из уроков с ответами**, **пропуск
заданий с галочками при сборке Word**, **самостоятельный переход на первый шаг плана, когда
текущий шаг в план не входит**, **запрет второго обхода, пока идёт первый**, а также поведение
ИИ: **в запросе к бесплатному сервису нет ни одного ключа**, **ничего не вставляется и не
отправляется**, **соблюдается лимит один запрос в 15 секунд** и **на шагах с готовым ответом
ИИ не вызывается**. Отдельно проверено, что скрипт **никогда не пишет в `answers/`** — только
в `inbox/` — и что после сохранения ответ не теряется из локального списка, пока отстающий
CDN не отдаст свежий `index.json`.

Интерфейс проверяется на настоящей разметке Stepik (ряд настроек урока и боковое меню курса):

- **кнопка добавлена в `.lesson-controls`** отдельным пунктом ряда, в родном классе
  `button_style_secondary`, и не ломает существующие пункты (их остаётся столько же);
- **панель встаёт внутрь `.lesson-sidebar__content`** и прячет список уроков, а крестик
  **возвращает уроки на место**; повторное нажатие кнопки открывает панель снова, а не залипает;
- список «с» **наполняется уроками из меню курса** — их ровно столько, сколько в сайдбаре.

И про каналы ИИ: **HTTP 402 у бесплатного → автоматический переход на свой канал** с ключом в
заголовке и моделью `glm-5.3-flash` (в теле запроса ключа нет), **внятное объяснение, когда
молчат оба**, **отсутствие обращений в свой канал, если ключ убран**, **работа встроенного ключа,
когда своего нет**, и **разбор ответа reasoning-модели, у которой пустой `content`**.
